# ЛР2 — поведенческие признаки для Marketplace Fraud Detection

Постройте модель `is_fraud` (0 — честное обращение, 1 — мошенническое)
из сырых событий. Команда проверки может обработать максимум 15% обращений.

## Файлы и поля

- `users.csv`: `user_id` — ключ; `registered_at` — регистрация;
  `country` — страна; `device_type` — устройство при регистрации;
  `is_verified` — статус, установленный при регистрации и неизменный в этой работе.
- `orders.csv`: `order_id`, `user_id`; `created_at` — создание заказа;
  `delivered_at` — доставка; `product_category` — категория;
  `order_amount` — стоимость; `payment_method` — оплата;
  `delivery_days` — время доставки в днях.
- `claims_train.csv`, `claims_test.csv`: `claim_id`, `order_id`, `user_id`;
  `created_at` — момент обращения; `claim_type` — причина;
  `claim_amount` — сумма возврата; `product_category` — категория заказа.
  Небольшая доля требований превышает стоимость заказа — это намеренные аномалии.
- `claim_history_outcomes.csv`: `claim_id`, `decision_at`, `is_fraud` —
  доступные результаты расследования старых обучающих обращений.
  Это снимок решений, известных до начала тестового периода.
  Здесь нет решений по тестовым обращениям. Отсутствие решения не означает 0.

Обучающие метки включены в архив: `train_labels.csv` (`claim_id`, `is_fraud`).
Присоединяйте их к `claims_train.csv` по `claim_id` для обучения модели.
История расследований не заменяет полный набор обучающих меток. Метки текущих
обращений служат целью обучения, а не признаками. Цель тестовой части скрыта.

## Время и признаки

Все даты — UTC без указания часового пояса. Период: 2024-01-01 — 2025-12-31.
Граница train/test: 2025-08-07 00:00:00; это первые 80% календарного периода,
а не 80% строк. Последний период содержит изменения распределений.

Для обращения в момент t используйте события строго раньше t. Окно D дней:
`t - D <= event_time < t`. Текущее обращение исключайте из истории claims.
Связанный заказ уже создан до обращения и включается в историю заказов.
Если заказ ещё не доставлен на момент t, его будущая доставка неизвестна:
не используйте её при построении агрегатов. Отрицательные значения -1 можно
использовать для интервалов без предыдущего события, 0 — для пустых агрегатов.

Результат расследования можно использовать только при `decision_at < t`.
Делите сумму известных fraud на число известных решений, не на число всех claims.
Даже опубликованная метка старого train-обращения может быть недоступна в момент t.
Не включайте текущее решение или агрегаты по полной истории пользователя.
Сырые таблицы содержат будущие события: фильтрация по времени обязательна.

Разделяйте train/validation по времени; random split запрещён для итоговой оценки.
Для последовательной оценки test более ранние test-обращения известны как события,
но их исходы неизвестны. Порог выбирайте на временной validation. Сообщайте ROC-AUC,
PR-AUC (average precision), Precision, Recall и долю отправленных на проверку.
На test соблюдайте бюджет 15%; допустим выбор верхних 15% по score без меток.
ID нужны для объединений, не используйте их как признаки модели.

Итоговый файл `predictions.csv`: `claim_id`, `fraud_probability`,
`is_fraud_prediction`. Не обращайтесь к преподавательским файлам при оценке test.
